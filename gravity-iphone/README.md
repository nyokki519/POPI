# オカマ読み上げスッキリアプリ v0.4

iPhoneの画面配信を受け取り、**左側のアイコンに対応する白・灰色・淡い着せ替え色の吹き出し**を検出して、本文の新着だけを読み上げます。固定範囲の文字をすべて読む旧方式を置き換えました。

[起動画面のプレビュー（SEシミュレーター）](preview-v0.4.jpg)

## 見た目と名前

アプリ名・画面配信先名は「オカマ読み上げスッキリアプリ」です。起動画面は生花を模した生成写真を使ったフローラルデザインです。背景は同梱の静止画で、通信や常時アニメーションはありません。GRAVITYへ切り替えた際は写真のデコード画像を解放し、配信拡張には写真を同梱しません。

Xcodeのプロジェクト名・ビルドするファイル名は従来どおり `GravityReader.xcodeproj` / `GravityReader.app` です。iPhone上の表示名が変わります。

## 今回の変更

v0.4では、白い吹き出しに加えて灰色・一部の淡い色を検出します。暗い吹き出しの検出失敗を再現テストで修正しました。初めから表示されている履歴は引き続き読みません。画面全体の文字を読むフォールバックは追加していません。

「読まれないときの確認」では、選択したスクリーンショットを配信と同じ検出・Vision処理に渡し、本文枠の検出件数、認識した本文、認識範囲の緑枠を表示します。「音声だけテスト」と「認識した本文を試し読み」で音声出力も別に確認できます。画像・本文はメモリ内だけで扱い、バックグラウンド移行時に確認画像を解放します。これはライブ配信成功を保証する機能ではありません。

v0.3で追加した楕円・星形・低コントラストのアバター許容も維持します。実際の課金装飾すべてを検証したものではありません。

- 文字認識の前に小さい画像で吹き出しと左側の円形アイコンを照合します。座席アイコン、入力欄、キーボードのキー、アイコンのない案内枠は認識対象から外します。
- 複数行の本文は吹き出し単位にまとめます。ユーザーが本文中で「入室しました」「GRAVITY」と書いた場合は、語句だけを理由に除外しません。
- レイアウト判定は長辺640ピクセル以下。OCRは吹き出しの切抜きだけで、1回に新規2件まで。同じ見た目の結果はメモリ内に最大40件保持して再利用します。
- 通常1.2秒以上の間隔を空け、処理が重い場合や発熱時はさらに間隔を延ばします。OSが高温状態を報告した場合は認識を見送ります。
- 画面中のアプリ表示領域を検出し、寸法をその領域に対する比率で扱います。SEのピクセル数は固定していません。

**見た目による判定には限界があります。** 白色、灰色、一部の淡い色と左上寄りのアバターを対象とします。高彩度・透明・背景と一体化した吹き出し、アイコンが隠れた発言、形の異なるテーマ、特殊なポップアップは読み飛ばす場合があります。公式案内でも同じ外観で表示されれば区別できない可能性があります。判定に失敗しても画面全体を読む動作には戻しません。全機種・全テーマ対応を保証する版ではありません。

## Xcode 14.2で56/76付近から進まない場合

`ChatLayout.swift` の `directions.map` でSwift 5.7.2の型推論が失敗する問題を修正しました。同じSwift 5.7.2でエラーを再現し、修正版の型チェック・新着判定・レイアウトテストの成功を確認しました。`xcode14-compatibility.json` に記録しています。完全なXcode 14.2でのiOSビルドはユーザーのMacで確認が必要です。

v0.4は複数ファイルの変更を含むため、フルZIPを展開して新しいプロジェクトを開いてください。以前の1ファイルだけのパッチは使用しません。

## Macからの更新

このZIPはXcodeプロジェクトです。iPhoneでZIPを開くだけではインストールできません。Macはインストール時に必要ですが、使用時はiPhone単体です。

1. ZIPを展開し、新しい `GravityReader.xcodeproj` をXcodeで開きます。`GravityReader` と `Upload` の両ターゲットで Signing & Capabilities のTeamを自分のPersonal Teamに設定します。
2. 古いXcodeで「device support files」不足が出る場合は実行先を **Any iOS Device (arm64)** にし、Product → Buildでビルドします。
3. Product → Show Build Folder in Finder → Products → **Debug-iphoneos** から `GravityReader.app` を探します。シミュレーター用のものは使用しません。
4. Xcodeで ⌘＋Shift＋2 → 接続したiPhoneを選び、ロックを解除した状態で `.app` をInstalled Apps欄へドラッグします。必要ならiPhoneの設定 → 一般 → VPNとデバイス管理から自分の開発者を信頼します。

旧版ではユーザーがXcode 14.2／Personal TeamからiPhone SE（第3世代）iOS 26.3.1へこの経路でインストールし、アプリ起動・配信・音声出力を確認しました。**今回の修正版の実機動作と負荷は未確認です。** 環境によってインストールが失敗する場合は、エラーを確認して切り分けます。無料署名には期限があり、期限後は再ビルドが必要です。課金・有料開発者登録は行っていません。

## 使用

1. アプリを開き、画面配信ボタンから `オカマ読み上げスッキリアプリ` を開始します。マイクはオフです。
2. GRAVITYのルームへ移動します。最初に認識できた画面は基準となり、読みません。
3. 新しく出現し、2回確認された吹き出し本文を読みます。キーボードがコメントを覆う場合、隠れた発言は認識できません。
4. iPhone上部の画面配信表示、またはコントロールセンターから停止します。

混雑時は待機6件・8秒以内とし、古い読み上げは捨てます。画面の完全な入れ替わりでは再基準化するため、その間の発言を読む保証はありません。誤認識の確認中は音量を控えめにしてください。

PRIVATEは自分で聞く用途です。**ROOMのマイク経路への音声注入は未実装**です。スピーカー音をマイクが拾わないようイヤホンを推奨します。

## 読まれない場合の確認

1. 画面配信を停止します。GRAVITYのコメントが見える状態でスクリーンショットを撮ります。
2. 本アプリの「読まれないときの確認」→「スクリーンショットを選ぶ」から画像を選びます。
3. 本文枠0件なら見た目の検出失敗、枠あり・文字0件なら文字認識失敗です。本文が表示されたら試し読みを行います。
4. 音声だけのテストも聞こえない場合、音量・出力先・ルームとの音声競合を確認します。静止画の試し読みが成功しても、GRAVITY使用中のバックグラウンド音声は別途確認が必要です。

PHPickerで選んだ画像だけを使用し、写真ライブラリ全体への権限は要求しません。画像を開いた後の検査は自動です。

## 検証と制限

テストの版と実行結果は `validation.json` に記録します。

- 純粋Swift：新着判定・待機列、模擬入力、吹き出し／アバターの合成画像、キーボード・案内の除外、画面比率、負荷制御。
- Apple環境：生成した日本語の画像を実際のVisionに渡すテスト、キャッシュ再利用、複数の解像度、アプリと拡張のiOS SDKビルド。
- **未確認**：提供画像そのものをファイル入力しての自動照合、GRAVITYでの修正版の認識精度、SEを含む実機でのCPU・メモリ・発熱、他機種での同時使用。合成画像の通過やビルド成功は実機動作の証明ではありません。

画面・認識文字は保存／ネット送信しません。キャッシュは配信中のメモリのみ。ログは件数・処理時間だけです。音声開始エラーや連続OCRエラーでは配信を終了します。

## 開発

追加の外部ライブラリは不要です。`python3 scripts/generate-project.py` でXcodeプロジェクトを再生成できます（署名Team等の手動変更は初期化されるので通常は実行不要）。`bash scripts/test-core.sh` で純粋Swiftテスト、Macでは `bash scripts/test-native.sh` で実際のVisionを用いた合成画像テストを実行します。

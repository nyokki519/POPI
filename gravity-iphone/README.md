# オカマ読み上げスッキリアプリ v0.8

**軽量・吹き出し優先版**です。v0.7で実機の読み上げは確認できた一方、余計な文字と重い動作が報告されたため、音声経路は維持し、認識対象と処理量を見直しました。

[起動画面](preview-v0.7.jpg) ／ [Windowsからの導入](WINDOWS.md)

## 今回の変更

- 名前やアイコンの一致は要求せず、塗られた吹き出しの面の中の文字を読みます。白・灰色・濃色・色付きの面を対象にし、背景上の名前や操作文字は減らします。面のない透明な表示や背景と同色の本文は見逃す場合があります。
- 画像判定の長辺を640から192へ縮小。通常経路では小さい画像の色領域のみを調べ、円形アイコン探索などは実行しません。
- 吹き出しがなければOCRを実行せず、見つかった面の周囲だけを1回で認識。長辺1000・22万画素以下に制限します。
- 吹き出しの外のアニメーションや画像変更だけではOCRキャッシュを無効化しません。同じ吹き出しは再利用します。
- 通常3秒以上、処理に時間がかかればその約10倍を次の認識までの間隔とします（最大30秒）。高温時は8秒以上、危険な発熱時は停止。短時間で消えた発言は見逃す場合があります。
- XcodeのDebugビルドも `-O` に変更。MacからDebug-iphoneos版を入れる場合も、画素走査を最適化して動かします。通常のソースデバッグは追いにくくなります。
- 英字・日本語3列キーの格子、右側の座席、下部操作欄は除外。ユーザー発言と同じ外観の案内は残る可能性があります。
- 開始の声、1回の認識での新着判定、待機上限60件・90秒・1件2000文字は維持しています。

## Macからの導入・更新

フルZIPを展開し、新しい `GravityReader.xcodeproj` を開きます。

1. `GravityReader` と `Upload` 両ターゲットの Signing & Capabilities → Team に自分のPersonal Teamを設定します。
2. 古いXcodeでdevice support files不足が出る場合は、実行先を **Any iOS Device (arm64)** にし、Product → Buildを実行します。
3. Product → Show Build Folder in Finder → Products → **Debug-iphoneos** の `GravityReader.app` を探します。
4. ⌘＋Shift＋2 → 接続したiPhoneを選び、ロック解除した状態で `.app` をInstalled Appsへドラッグします。必要ならiPhoneの設定 → 一般 → VPNとデバイス管理から自分の開発者を信頼します。

無料署名には期限があります。別のiPhoneにも、その端末用の署名が必要です。Windowsは [WINDOWS.md](WINDOWS.md) のAltStore Classicによる署名手順を使用します。署名前IPAを直接開いてもインストールできません。

## 使用と切り分け

1. アプリの配信ボタンから開始します。マイクはオフです。
2. 「読み上げを開始します」の声を確認し、GRAVITYのルームを開きます。
3. 最初から表示中の吹き出しと、その後に認識された新しい本文を読みます。
4. 停止はiPhoneの画面配信表示、またはコントロールセンターから行います。

開始の声が聞こえなければ、文字選択だけでは解決できない音声経路・配信拡張の問題が考えられます。開始の声は出るがコメントが読まれない場合は、「読まれないときの確認」で実際のルーム画像を選び、対象文字が出るか確認できます。静止画での成功は配信中の動作証明ではありません。

PRIVATEは自分で聞く用途です。ルームのマイクへの音声注入は未実装です。実音量・出力先・GRAVITYとの同時使用時の音声は実機確認が必要です。

## 負荷・検証の範囲

実行結果と対象コミットは `validation.json` に記録します。合成ルームを使い、同じApple環境・最適化済みコードで旧広域処理と新処理の中央値を比較します。この測定は実際のiPhoneやGRAVITYのCPU・発熱・操作感の測定ではありません。

ReplayKit自体の画面取得コストは残ります。端末・ルームの演出・OSなどで負荷が変わるため、実機で操作できるまで軽くなったことは未確認です。認識頻度を下げた分、読み上げまでの遅れや取りこぼしは増える場合があります。

画像・認識文字は保存・外部送信しません。件数・処理時間・音声開始／完了状態のみログに出します。花の起動画面とアイコン、Windows再署名後の配信拡張IDの検出は維持しています。

## 開発

```
bash scripts/test-core.sh
python3 scripts/generate-project.py
```

Apple環境では `bash scripts/test-native.sh`。CIはアプリと拡張の両方をビルドします。旧構造・v0.7広域処理は明示的に指定した回帰／比較用経路として保持し、通常の配信・画像診断では新しい軽量処理を使用します。Swift 5.7.2共通処理の検証と完全なXcode 14.2でのビルドは区別し、後者は未確認です。

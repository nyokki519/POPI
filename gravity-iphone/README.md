# オカマ読み上げスッキリアプリ v0.7

**読み落とし優先版**です。チャット領域の文字を広く読み、アイコン・名前・吹き出しの有無や色で発言を落とす判定を外しました。名前・入室履歴・運営アナウンスも読まれる場合があります。

[起動画面](preview-v0.6.jpg) ／ [Windowsからの導入](WINDOWS.md)

## 今回の変更

- 広い領域のOCR結果をそのまま読み上げ候補にします。画像アイコン・本文枠・ユーザー名の対応付けを必須にしません。
- 除外は、画面上端17%・下端10%、右端から始まる文字、格子状のキーが明確なキーボード、読み上げアプリ自身の固有操作ボタンの組み合わせです。右まで伸びた本文は左側から始まっていれば残します。固定領域にコメントが表示される画面配置では取りこぼす場合があります。
- 日本語3列キーと英字キーボードを検出します。未知のキーボード、予測変換欄、入力欄の移動には完全対応を保証しません。確実にキーと判断できない文字は読み残します。
- OCRの信頼度は0.2以上を許容。1回の認識で候補へ渡し、開始時の画面も読ませます。途中の行が後から認識された場合も渡します。似た文章を誤字として同一視しません。
- 同じ表示内容は再読を抑制。重なりのない画面では、直近20秒に認識していない各行を読みます。同文の発言が再出現した場合の抑制や、OCRの揺れ・履歴スクロールによる再読は残ります。
- 読み上げ待ちは60行・90秒まで、1行2000文字までに緩和しました。発言が多いと遅延し、上限を超えた待機分は破棄します。無制限に溜めないための上限です。
- 配信拡張から「読み上げを開始します」と発声します。これはホストアプリの音声テストとは別で、実際の配信拡張の音声経路を使います。

## Macからの導入・更新

フルZIPを展開し、新しい `GravityReader.xcodeproj` を開きます。

1. `GravityReader` と `Upload` 両ターゲットの Signing & Capabilities → Team に自分のPersonal Teamを設定します。
2. 古いXcodeでdevice support files不足が出る場合は、実行先を **Any iOS Device (arm64)** にし、Product → Buildを実行します。
3. Product → Show Build Folder in Finder → Products → **Debug-iphoneos** の `GravityReader.app` を探します。
4. ⌘＋Shift＋2 → 接続したiPhoneを選び、ロック解除した状態で `.app` をInstalled Appsへドラッグします。必要ならiPhoneの設定 → 一般 → VPNとデバイス管理から自分の開発者を信頼します。

無料署名には期限があります。別のiPhoneにも、その端末用の署名が必要です。Windowsは [WINDOWS.md](WINDOWS.md) のAltStore Classicによる署名手順を使用します。署名前IPAを直接開いてもインストールできません。

## 使用と切り分け

1. アプリの配信ボタンから開始します。マイクはオフです。
2. 「読み上げを開始します」の声を確認し、GRAVITYのルームを開きます。
3. 最初から表示中の文字と、その後に認識された新しい行を読みます。
4. 停止はiPhoneの画面配信表示、またはコントロールセンターから行います。

開始の声が聞こえなければ、文字選択だけでは解決できない音声経路・配信拡張の問題が考えられます。開始の声は出るがコメントが読まれない場合は、「読まれないときの確認」で実際のルーム画像を選び、対象文字が出るか確認できます。静止画での成功は配信中の動作証明ではありません。

PRIVATEは自分で聞く用途です。ルームのマイクへの音声注入は未実装です。実音量・出力先・GRAVITYとの同時使用時の音声は実機確認が必要です。

## 負荷・検証の範囲

認識画像は長辺1280以下・40万画素以下、配置判定用画像は長辺640以下。同じ画像の結果はメモリ内で最大12件再利用します。通常1.2秒以上の間隔を空け、処理が重い場合や発熱時は間隔を延ばします。高温時は見送ります。認識の間に現れて消えた文字や、OCR自体が認識できない文字は拾えません。

実行結果と対象コミットは `validation.json` に記録します。旧版の厳密な構造判定は回帰検証用に保持し、通常の配信・画像診断は読み落とし優先の経路を使います。合成画面のVision検証とビルドを、GRAVITY実機での音声・精度・負荷の検証とは区別します。100%の読み取り、全端末・全テーマ・将来OSへの対応は保証していません。

画像・認識文字は保存・外部送信しません。件数・処理時間・音声開始／完了状態のみログに出します。花の起動画面とアイコン、Windows再署名後の配信拡張IDの検出は維持しています。


# v0.7 読み落とし優先

ユーザーが案内等の混入を許容したため、通常経路を形状選別から広域文字読み取りに変更。`readingLines` は端の操作領域・明確なキー格子・自身の固有ボタン対だけを除外する。アイコン・名前・背景色・輪郭は使用しない。旧 `structuralMessages` は旧版回帰用に残し、通常のChatFrameProcessorは広域経路を既定とする。

`CommentDetector.recallMode` は初期画面と新規行を1回で渡す。LCSで対応しなかった行を途中の位置からも拾う。重なりのない画面は直近20秒の文字履歴で再読を抑制し、未知の行は全て渡す。厳密な本文一致を使い、OCR信頼度は0.2以上。既存の通常／liveModeのテストは維持する。

配信拡張で開始の短い発声を行い、OCR前の音声経路を端末上で切り分けやすくする。音声セッション自体は初期成功版と同じ。待機上限は60行・90秒・1行2000文字。画面バッファを保持せず、元の画像サイズ・OCR間隔・キャッシュ上限を維持する。

失敗を再現したテストは、初期文字・短時間の発言・入れ替わった全行・低信頼度・途中への行追加・似た別文章の抑制。広域経路はアイコンなし・アナウンス許容・操作領域除外・幅広本文・英字／日本語3列キー除外を検証する。ネイティブの旧構造テストと、新しい既定経路のテストを区別する。実際のGRAVITYでの認識・聴取・負荷は未検証。

# v0.5 構造に基づくコメント抽出

- 入力文字は広い左・中央領域から1回のVision OCRで取得。長辺1280・40万画素上限。位置を元画像の正規化座標へ戻し、縮小画像のアイコンと照合する。
- `structuralMessages` は画像アイコンの横の名前行を探し、その下の本文行を次の名前までまとめる。塗り色・閉じた吹き出し輪郭は判定条件にしない。円形境界に加え、模様と複数辺の境界を持つ写真状パッチを許容する。
- 右の座席・下の操作欄・アイコンなし・本文なしは除外。キーボードは色を固定せず局所色差で連結したキーの反復行を検出する。文字だけに対する未知UI全読みのフォールバックはない。
- 元バッファをコールバック越しに保持しない。文字結果のキャッシュ12件、温度／処理時間による実行間隔制御、既存の新着・重複・鮮度管理を維持。実機の負荷低減は未検証で、広域OCRに伴う処理量増加もあり得る。
- 花＋音波の生成画像をAppIconアセットの18スロットに設定。RGB・透過なし。背景写真は従来どおりホストのみ。
- 同じCIのiPhone用ビルドからPayload形式の署名前IPAを作る。シミュレーター用を拒否、配信拡張・Assets.car・必須メタデータを検査し、GitHub上にダウンロード用ファイルを公開。AltStoreによる再署名と実機導入は別工程で未検証。
- 共通ロジックはSwift5.7.2で実行。実Visionテスト、CI、対象ソース、成果物の検査結果はvalidation.json参照。旧色判定のテスト28件は従来ヘルパーの回帰検証であり、新方式の実機精度を示すものではない。

追加起動確認では、起動12秒後のプロセス生存を確認し、再前面化後の実アプリ画面を撮影して目視確認。初回3秒撮影でホーム画面になった点を、この確認で切り分けた。Windows実機やGRAVITY同時使用の検証は行っていない。

# v0.4 読み取り改善・診断

- 再現1：白色限定で灰色・淡青色の本文枠を見つけられない。失敗する合成画像テスト2件を作成し、明るい領域と低彩度領域を別々に検出する変更で通過。左側アバターと形状条件は共通で維持。
- 再現2：暗いキーを持つキーボードの近くに既存アバターがあると誤って本文扱いする。暗色キーの回帰テストで失敗を確認し、キー行の検出にも両方の色群を使用して修正。
- 調査3：初期の空画面後に届く最初の発言が基準として無音になることを確認。空画面2回を基準とする案はテストを通過したが、別アプリやキーボードによる非表示と空ルームを区別できず、ルームへの切替後に過去ログを読む危険があるため撤回。新着判定は従来の安全側の動作を維持し、取りこぼしの制限を明記。
- 診断：ユーザーがPHPickerで選択したスクリーンショットを同じChatFrameProcessorへ渡す。最大10切抜き、1呼び出し2件の上限を維持し、最大6呼び出し。本文枠の数と文字列を表示し、認識成功した本文枠を緑色表示する。音声単体・認識本文の試し読みを別に用意。画像や本文の保存・外部送信なし。
- 診断画像はバックグラウンド移行時に解放。画像読み込みの非同期応答は世代番号で無効化し、古い選択結果による上書きを防止。
- 配信ログは10秒ごとの件数・処理時間だけ。0件も記録し、形状検出とOCRのどちらで失敗しているか診断可能にする。文字内容はログに出さない。
- Swift 5.7.2 Linux：新着・待機列32件、レイアウト・負荷制御28件、設定、24フレーム模擬入力を通過。UIKit/Visionの実行結果はvalidation.json参照。Linuxでの構文確認だけをiOS動作検証とは扱わない。
- 制限：高彩度・透明・背景と同色の吹き出しや未知の装飾は未対応の場合あり。全画面が入れ替わり既存発言との重なりが消えた場合は引き続き基準化するため、新着の取りこぼしは残り得る。GRAVITY実機での精度・バックグラウンド音声・負荷は未検証。写真選択画面の実機操作も未確認。

# v0.2 実装・検証記録

目的：GRAVITYのユーザー発言だけを読み、入室案内・公式案内・キーボード等の誤読とバックグラウンド負荷を減らす。ユーザーが提供したルーム画像の外観を手掛かりに実装。

- 原因：旧版は画面の45〜90%へ無差別にOCRを適用し、外観による発言判定がなかった。
- 対策：縮小画像の明るい連結領域と、その左上側の円形エッジを組み合わせる。本文だけを切り抜いて認識。画面内のアプリ領域に対する比率を使用し、画素数を固定しない。
- 保守的な動作：見た目が未対応なら読み飛ばす。全画面OCRへのフォールバックは行わない。意味内容を推測して公式／ユーザーを分類しない。
- 負荷：長辺640の判定、クロップ上限800／15万画素、1回のOCR上限2件、40件キャッシュ、1.2秒以上の認識間隔、実測処理時間・発熱に応じた間隔調整。複数件は元バッファを保持せず合計約6MB以下の画素コピーから順に認識する。
- 追加レビュー：上部の装飾変化で下の未認識コメントが永久に待たされる問題を指摘。変更が続く3吹き出しのネイティブテストで失敗を確認（run 38737570583）。1画面のバッチを完了する方式へ変更し、Apple環境の同じテストで通過を確認。6秒を超えた未完了バッチは破棄。読み上げ待ちの時刻は画面を取り込んだ時刻を使用する。
- 回帰：短い吹き出しを見落とす条件と、横幅の広い画面でキーボードが古いアバターと結び付く条件をそれぞれ失敗→修正→成功で確認。
- 検証：純粋Swift新着判定32件・レイアウト／負荷制御20件、設定テスト、24フレーム模擬入力。Apple Visionの合成日本語画像で本文抽出、キャッシュ、750×1334／1170×2532／1290×2796、装飾変化、向き補正、キーボード除外を検証。最終CIはvalidation.jsonに記録。

実機のCPU・メモリ・発熱は測定していない。提供スクリーンショットそのものの自動画像テストは行っていない。全機種／テーマ対応、公式アカウントが通常ユーザーと同じ外観を使う場合の識別は保証しない。実機での精度と快適さは更新後の確認が必要。
